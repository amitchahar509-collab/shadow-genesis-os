## 1. WHAT ACTUALLY WORKS (verified by tests + live execution)

### 1.1 Agent Runtime — REAL ✅
- `BaseAgent.execute()` lifecycle: allocates sandbox, persists AgentExecution row, logs every tool call to ToolCall table, persists artifacts with sha256 checksums, records episodic memories on start/success/failure.
- 13 agents registered: CEO, RESEARCH, ARCHITECT, ENGINEERING, DESIGN, GROWTH, QUALITY, DEPLOYMENT, SECURITY, OPPORTUNITY, BUSINESS_VALIDATION, REVENUE, INTERNET.

### 1.2 Tool Execution Layer — REAL ✅
- 7 tools: filesystem, terminal, code, api, browser, git, package.

- Every tool call logged to ToolCall table with duration + status + error.

### 1.3 Task Orchestrator — REAL ✅
- `dispatchGoal()` → CEO decomposes → `runPipeline()` runs tasks in parallel where deps allow.
- Per-agent mutex (no parallel runs of same agent).
- Retries with backoff. Deadlock detection. Blocked-on-failed-dep handling.
- `startMission()` runs in background, returns immediately with mission id.
- Live verification: 33 orchestrator tests pass.

### 1.4 Memory Engine — REAL ✅
- 3 memory types: EPISODIC, SEMANTIC, PROCEDURAL.
- Ranked recall: tag match (5pts) + title token overlap (3pts) + content overlap (1pt) + importance (0.5x) + recency (2pts if <24h).
- Jaccard similarity for `similarMissions()`.
- `failurePrevention(tool, operation)` recalls past failures.
- `consolidate()` groups episodic by tag, creates procedural SOPs when ≥3 entries.
- Verified by 6 memory tests.

### 1.5 Persistence — REAL ✅

- SQLite (swappable to Postgres via DATABASE_URL).
- Every agent action creates real DB rows.

### 1.6 API Surface — REAL ✅

## 2. WHAT IS SIMULATED / FAKE (must remove or replace)

### 2.1 Activity Service — FAKE ❌
**File**: `mini-services/activity-service/index.ts`
**Problem**: Still contains the V2 fake template generator. Every 2.5-5s it picks a random template from a hardcoded list of ~40 fake events ("Compiled dashboard route — 0 errors", "Ran 142 tests · 141 passed", etc.) and broadcasts them as if they were real agent activity.
**Impact**: Dashboard activity feed shows fake events mixed with real ones. Users cannot tell what's real.
**Fix**: Replace with real-event broadcaster (HTTP `/broadcast` endpoint that accepts events from the runtime's event-bus, no fake templates). Keep socket.io protocol for dashboard compatibility.

### 2.2 Seed Data — INTENTIONAL NARRATIVE ⚠️
**File**: `src/lib/genesis/seed.ts`
**Problem**: Seeds 25 tasks, 8 departments, 12 memories, 8 loops, 6 decisions, 6 research reports, 20 activity logs, 10 metrics, 5 checkpoints. These are labeled as "narrative" but appear alongside real data.
**Impact**: Dashboard shows seeded (fake) tasks alongside real agent-created tasks. Confusing.
**Fix**: Add a `seeded` flag to seed data, or provide a "clear seed" button. Default to showing only real data; seed data only on first install.

### 2.3 Dashboard UI — V2 ONLY ❌
**File**: `src/components/genesis/genesis-shell.tsx` + `sections/`
**Problem**: UI has only 6 V2 tabs (Command Center, Task Graph, Departments, Memory Banks, Operational Loops, Genesis State). NONE of the V3/V4 features are exposed:
- No "Build my idea" mission input
- No agents tab (13 agents invisible)
- No executions tab
- No missions tab
- No messages tab (collaboration graph invisible)
- No security tab
- No observability/metrics tab
- No opportunities tab
- No projects tab
- No decisions/approval queue
- No sandboxes tab
**Impact**: Users cannot use any V3/V4 feature from the UI. The product looks like a static dashboard.
**Fix**: Build a new dashboard with all V4 features exposed. This is the BIGGEST gap.

## 4. WHAT IS FRAGILE

### 4.1 LLM Calls Without API Key — FRAGILE ⚠️
- All agents fall back to rule-based logic when `ZAI_API_KEY` is not set.
- Fallbacks work but produce lower-quality output (e.g., CEO's rule-based plan is always the same 7-task pipeline regardless of goal).
**Fix**: Document `ZAI_API_KEY` requirement in README + `.env.example`.

### 4.2 Synchronous Orchestrator Under Load — FRAGILE ⚠️
- `startMission()` runs in background but the CEO's LLM call (8s timeout) blocks the event loop.
- Multiple concurrent missions can starve the process.
**Fix**: Already mitigated by per-agent mutex. For production, extract to worker process.

### 4.3 SQLite Concurrency — FRAGILE ⚠️
- Single writer. Under parallel agent execution, Prisma writes contend.
**Fix**: Already mitigated by keeping writes short. For production, switch to Postgres.

### 4.4 No Process Cleanup on Crash — FRAGILE ⚠️
- If the server crashes, sandbox child processes (detached dev servers) keep running.
**Fix**: Sandbox manager has TTL cleanup, but it only runs when the server is up. Add a startup sweep.
