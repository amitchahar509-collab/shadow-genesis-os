## Remaining Limitations

### 1. No User Authentication (HIGH)
- No User model, no login/signup, no sessions
- Anyone can call any API endpoint
- **Mitigation**: Run behind a firewall / VPN in production
- **Future**: Add NextAuth with User model

### 2. LLM Dependency (MEDIUM)
- Without `ZAI_API_KEY`, agents use rule-based fallbacks
- Fallbacks work but produce lower-quality output (e.g., CEO always generates the same 7-task plan)
- **Mitigation**: Set `ZAI_API_KEY` env var
- **Future**: Support multiple LLM providers

### 3. SQLite Concurrency (LOW)
- Single writer. Under heavy parallel agent execution, writes contend.
- **Mitigation**: Per-agent mutex limits parallelism
- **Future**: Switch to Postgres via `DATABASE_URL`

### 4. Synchronous Orchestrator (LOW)
- Background missions run in-process. Heavy missions can starve the event loop.
- **Mitigation**: Per-agent mutex; LLM calls have 8s timeout
- **Future**: Extract agent runtime to a worker process

### 5. No CI Pipeline (LOW)
- No automated test/build on commit
- **Mitigation**: Run `bun test && bun x tsc --noEmit && bun x eslint src/ tests/ && bun run build` manually
- **Future**: Add GitHub Actions workflow

### 6. Seed Data Mixes with Real Data (LOW)
- V2 seed data (25 tasks, 20 activity logs) appears alongside real data
- **Mitigation**: Use `DELETE /api/genesis/seed` to clear (when implemented)
- **Future**: Add "seeded" flag or separate seed namespace
